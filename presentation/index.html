1. Executive Summary

The **CoEDM Smart Manufacturing Control Software** unifies 7 heterogeneous machines under a single browser-accessible HMI portal, replacing individual manual PLC terminals with a single centralized software layer.

cancel Before: Factory Floor Silos

  • Operators walked to separate physical PLC screens to issue commands.
  • No historic data logging; vibration sensors lacked trend analysis.
  • No software dispatch; AMRs required manual coordination.
  • Safety curtains acted as local cut-offs; lacked HMI lockouts and notifications.

check_circle After: Unified Automation Layer

  • Single, secure web HMI for all stations on the local network.
  • TimescaleDB time-series storage for 10Hz sensor data.
  • E-Commerce integration: customer purchases trigger physical shuttle retrieval.
  • Intelligent safety lockout overlay disables controls instantly during faults.

Three-Tier Architecture

Decoupled boundaries provide high performance and guard low-level PLCs:

Layer What was used How it was used How it is helpful
Tier 1: HMI React 18, Vite, Tailwind CSS, Recharts SVG Maintains global status via wsCache.js. Bypasses React updates for 60fps animations. Prevents UI freeze and HMI lag during high-frequency data streams.
Tier 2: Core FastAPI (Python 3.11), asyncio Runs asynchronous loops for connection health and serializes gateway reads. Handles hundreds of telemetry signals concurrently without blocking.
Tier 3: DB PostgreSQL 15, TimescaleDB extension SQL transactions coordinate with PLC states; sensor telemetry writes to partitioned hypertables. Guarantees data integrity and ensures rapid historical index searches.

4. Communication Protocols

How the central platform bridges and coordinates heterogeneous industrial hardware:

Protocol What was used How it was used How it is helpful
OPC-UA asyncua Client Resolves tags, subscribes to LED changes, and sends 500ms command pulses to PLCs. Standardizes machine controls, removing the need for manual HMI walks.
Modbus TCP pymodbus, gateway singletons Polls vibration registers via a shared gateway. Dispatches navigation targets to the AMR. Coordinates low-cost register-based sensors and mobile robots.
Raw TCP Socket streams, Techman TMSCT Wraps movement command arrays inside script packets containing custom XOR checksums. Enables direct script execution on the TM Cobot from the central server.
Websocket FastAPI WebSockets, deep diff Transmits only the differences (delta frames) to client HMI browsers every 100ms. Saves local network bandwidth and reduces client parsing loads.

5.2 CNC Spindle Vibration Analytics

VibIT vibration sensors are physically bolted to the main spindle housing of the MIRAC Lathe and TRIAC Mill to monitor bearing wear and tool integrity. The sensor internally processes high-frequency analog waveforms into a root-mean-square velocity ($V_{RMS}$) in units of $g$ RMS:

Nominal < 0.05 g

Normal spindle operation. Healthy vibration envelope. Standard machining speeds are allowed.

Warning 0.05 - 0.12 g

Degraded spindle bearing state or tool wear. Logs warning alert events and flashes status overlays on the HMI.

Critical Lockout > 0.12 g

Critical threshold. Sends cycle stop pulse directly to CNC OPC-UA tag and blocks further HMI control inputs.

What was used How it was used How it is helpful
Modbus TCP Singletons & RLock serialization Funneled multi-node register reads through a class-level registry client, executing queries sequentially with word-swapped float32 decoding. Allows continuous telemetry reads without causing socket connection drops on physical VibIT gateways.

5.4 AMR Navigation & Floor Map

Autonomous Mobile Robots coordinate transport routes between 7 station coordinate zones in real-time:

  • Station coordinates: Zone coordinates (Home, ASRS, Lathe, Mill, Press, Inspection, Testing) mapped to physical factory coordinates in meters.
  • Arrival check: Radial threshold math determines when target coordinates are reached: hypot(x1 - x2, y1 - y2) < 0.25m.
  • Interpolation: Plots in-transit coordinates dynamically onto HMI floorplans using weighted distance calculations.

  • Manual connect: Connections are established via HMI triggers rather than at server startup.
  • Failure protection: Prevents startup loops if the AMR is powered off or charging.
  • Reconnect backoff: Attempts up to 3 reconnection loops with 1-second backoffs before raising alarm events.

6. WebSocket Delta Protocol

State change payloads are optimized using snapshot-delta frames to minimize network overhead on the local factory LAN:

history Standard Snapshot Payload

  • Sent immediately on initial client WebSocket handshake connection.
  • Contains complete system state records and inventory maps.
  • Payload size is ~3.2 KB.
  • Useful for aligning states at launch, but expensive for frequent updates.

flash_on WebSocket Delta Update

  • Computes deep state changes every 100ms on the backend.
  • Sends *only* changed key-value pairs (deltas) over the socket.
  • Payload size is reduced to ~0.2 KB (93% compression).
  • Saves up to 80% network bandwidth and speeds up client JSON parses.
What was used How it was used How it is helpful
FastAPI Websockets & JSON delta diffs Compared current telemetry variables with last broadcast frames, sending only changed fields using fast orjson serializations. Prevents network congestion and HMI visual lag, keeping client HMI performance stable.

7. TimescaleDB Time-Series Model

High-frequency sensor data is stored efficiently by combining relational models with partitioned hypertables:

storage Database Partitioning

  • Hypertables: Partitions high-frequency telemetry records (such as vibit_readings) based on timestamp intervals.
  • Interval chunking: Configured for 1-day partitions to align memory maps and index allocations.
  • Metadata tables: Standard PostgreSQL tables manage relational entities (users, orders, machines).

analytics Operational Value

  • Index scale: Chunking indexes prevents DB memory swaps and leg updates as tables grow.
  • Timescale queries: Enables rapid queries for historical vibration trends and average equipment performance.
What was used How it was used How it is helpful
TimescaleDB Hypertables Converted telemetry records to hypertables using the create_hypertable command, partitioning records by timestamp. Avoids database slowdowns and index bloat, maintaining fast queries under high time-series workloads.

9. Key Engineering Decisions

Design trade-offs implemented to maintain physical reliability and software safety:

1. Database-First AS/RS Operations

PLC write calls reside inside SQLAlchemy database transaction blocks. Commits execute *only* when the hardware completes movements. Ensures database registers never show slots as empty if the mechanical retrieve fails.

2. Modbus Client Serialization Gateway

The physical VibIT gateway accepts only one concurrent socket link. Multi-threaded sensor reads are funneled through a registry class and serialized using an `RLock`, preventing connection drops.

3. Direct-DOM SVG Rendering Bypass

Vibration updates arrive at 10Hz. Binding coordinates to React state creates jerking during page reconciliation. Rendering coordinates directly to the DOM using `requestAnimationFrame` maintains stable UI updates.
